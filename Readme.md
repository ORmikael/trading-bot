### Data Organization

The `data/` directory follows a strict data lifecycle:

```text
data/
├── raw/          # Original files exactly as downloaded
├── extracted/    # Files extracted from downloaded archives
├── normalized/   # Clean, standardized market data
├── processed/    # Derived datasets prepared for analysis/backtesting
└── results/      # Outputs generated by the backtester
```

#### `raw/`

**Exactly what was downloaded from the original data source.**

Nothing in this directory should be modified, reformatted, or overwritten.

Example:

```text
raw/
└── EURUSD/
    └── TrueFX/
        ├── eurusd-2026-01.zip
        ├── eurusd-2026-02.zip
        └── eurusd-2026-03.zip
```

This directory serves as the **immutable source-of-truth archive**.

---

#### `extracted/`

**The contents extracted from the original source archives, without transforming the data.**

The files remain in the format provided by the data source.

Example:

```text
extracted/
└── EURUSD/
    └── TrueFX/
        ├── EURUSD-2026-01.csv
        ├── EURUSD-2026-02.csv
        └── EURUSD-2026-03.csv
```

The data should still represent the source data exactly; this layer exists primarily to separate archive extraction from data processing.

---

#### `normalized/`

**Source data converted into a consistent internal format.**

This is where we standardize things such as:

* timestamps
* symbol names
* bid/ask fields
* numeric precision
* spread
* mid-price
* data types
* ordering
* validation

Example:

```text
normalized/
└── EURUSD/
    └── ticks/
        ├── 2026-01.parquet
        ├── 2026-02.parquet
        └── 2026-03.parquet
```

The normalized dataset is the **canonical market-data layer** used by downstream components.

---

#### `processed/`

**Data derived from the normalized dataset for specific analytical or trading purposes.**

This layer contains transformations such as:

* OHLC bars
* resampling
* timeframe aggregation
* indicators
* features
* session data
* strategy-specific datasets

Example:

```text
processed/
└── EURUSD/
    ├── 1m/
    ├── 5m/
    └── 15m/
```

For example:

```text
normalized ticks
        ↓
    aggregation
        ↓
processed/EURUSD/1m/
        ↓
   strategy engine
```

Processed data can be regenerated from the normalized dataset and therefore **should not be treated as the original source data**.

---

#### `results/`

**Everything generated by the backtesting engine.**

This directory contains the outputs of experiments and simulations rather than market data.

Examples include:

* executed trades
* equity curves
* P&L
* drawdown
* win rate
* risk/reward statistics
* performance metrics
* strategy reports
* backtest configurations
* charts
* optimization results

Example:

```text
results/
└── EURUSD/
    └── strategy-name/
        └── run-YYYYMMDD-HHMMSS/
            ├── trades.csv
            ├── equity.csv
            ├── metrics.json
            ├── config.json
            └── report.html
```

Backtest results should be **reproducible** from the corresponding processed/normalized data and strategy configuration.

---

### Data Flow

The complete data lifecycle is:

```text
DATA SOURCE
    │
    ▼
raw/
    │
    │ extraction only
    ▼
extracted/
    │
    │ validation + normalization
    ▼
normalized/
    │
    │ transformation / aggregation
    ▼
processed/
    │
    │ backtesting
    ▼
results/
```

### Core Principle

> **Raw data is preserved. Extracted data is untouched. Normalized data is standardized. Processed data is derived. Results are generated.**

Each layer has a single responsibility, making the pipeline reproducible, auditable, and safe to regenerate.

# Running the Trading Bot Pipeline

Run the pipeline from the project root.

## 1. Enter the project

```bash
cd ~/projects/trading-bot
```

## 2. Activate the virtual environment

```bash
source trading-bot-venv/bin/activate
```

You should see:

```text
(trading-bot-venv)
```

in your terminal prompt.

## 3. Verify the dataset

Confirm the raw archives exist:

```bash
ls -lh data/raw/EURUSD/TrueFX/
```

Expected:

```text
eurusd-2026-01.zip
eurusd-2026-02.zip
eurusd-2026-03.zip
```

## 4. Run the pipeline

```bash
python main.py \
    --symbol EURUSD \
    --source TrueFX \
    --strategy range_pyramid \
    --timeframe 1m
```

## 5. Pipeline order

`main.py` will execute:

```text
Extraction
    ↓
Validation
    ↓
Normalization
    ↓
Bar Generation
    ↓
Backtest
    ↓
Results
```

If validation returns `FAIL`, the pipeline stops before normalization.

## 6. Check generated data

After a successful run:

```bash
find data/extracted -type f
find data/normalized -type f
find data/processed -type f
find data/results -type f
```

The backtest results should be under:

```text
data/results/range_pyramid/run-<RUN_ID>/
```

## 7. If something fails

The pipeline prints the failing stage and raises the original Python exception. **Do not modify multiple modules at once.** Debug the first failing stage, fix it, then rerun:

```bash
python main.py --symbol EURUSD --source TrueFX --strategy range_pyramid --timeframe 1m
```
